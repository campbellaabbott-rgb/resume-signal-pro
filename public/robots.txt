# (/analytics, /errors, /health-check, /scan-metrics), the Agent Pass receipt
# (/agents/pass — signed-in only, reads the buyer's own row) and the OAuth
# consent route (/oauth/consent — exists only for an agent host's authorization
# request), the market-pulse confirmation page (/market-pulse/confirm --
# opened only from a single-use link in a confirmation mail) and the fix-plan
# confirmation page (/fix-plan/confirm -- opened only from the button in a
# report mail) and the unsubscribe page (/email/unsubscribe -- opened only from
# the link in one of our mails) have zero search value and must never be indexed. (Lovable's
# route-vs-sitemap checker flags these as "missing" — that is expected; do NOT
# add them to the sitemap.)
# Disallow is repeated per named group on purpose: a crawler obeys only its own
# most-specific User-agent block and never inherits rules from "*". The list is
# the PRIVATE_ROUTES allowlist in src/test/sitemap-prerender-parity.test.ts,
# and src/test/the-board-hands-a-job-and-a-search-to-the-agent.test.tsx fails
# when any of those routes is missing from any block here.
# The developer tool at /dev/checkout-test is NOT disallowed: a crawler that
# may not fetch it can never read its noindex (the app's, and the small page
# the bake writes there), and a linked URL could still be indexed address-only.
# Every route under /admin/ is the owner's (today /admin/claims, the claims
# review): no page links one, and each served the homepage copy, indexable, to
# a reader that runs no JavaScript (SEO audit 2026-11-18, CRAWL-4), so every
# group disallows the folder. It is the /admin/ entry of PRIVATE_PREFIXES in
# src/test/sitemap-prerender-parity.test.ts.
# No group opens with a line that allows the whole site. Allowing is the
# default, so the line added nothing, and a reader that obeys the FIRST rule
# that matches (Python's urllib.robotparser, and small crawlers built on it)
# stopped there and read every private route below it as allowed. Google,
# Bing and RFC 9309 take the longest match, which these groups satisfy too;
# the guard parses this file both ways (SEO audit 2026-11-18, CRAWL-6).

# ONE SITEMAP, AND EVERY URL IN IT SERVES ITS OWN PAGE.
#
# A second Sitemap line used to point at an index the board function serves
# live. Measured 2026-09-23: it listed 767,391 URLs across 30 pages, every one
# of the form /jobs?job=<id> — and every one of those served, byte for byte,
# the same file as /jobs. Same MD5, the board's own title and description, a
# canonical naming /jobs, and no job markup in the served bytes; an id that
# does not exist returned the identical bytes too. So we were asking crawlers
# to index three quarters of a million copies of one page, and telling them on
# each copy that the page was really /jobs.
#
# Individual openings now have real pages (/jobs/posting/...), a bounded set of
# them is prerendered by scripts/prerender-seo.mjs, and exactly those are in
# sitemap.xml above. The rule and the number are printed on /jobs itself.
